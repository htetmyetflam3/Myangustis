ZawCode: leading-slot order, source evidence

Source: ယဲ့နင် စာစဉ် a ၁.merged.merged.pdf, pages 1–200 of 4,414.
Selected F1 embedded font SHA-256:
5bc0cd2994aa0178e01efb00f9217e9adb975ba86e77a12e6e8f81268c450de9

This source uses two-byte Identity-H codes with an Identity CID-to-GID map;
they are glyph IDs, not the ASCII slots in zawcode-layout.js. The evidence
uses that font's cmap and direct GSUB single substitutions without /ToUnicode.
These are provisional readings, not proof that a font name identifies the
keyboard layout. The sample includes page content streams only, not Form
XObjects. Raw evidence is kept separately from the ordered Unicode slots.

Examples (four hex digits per raw PDF code):
  page 1: 00E4 00EE 007E 00DF 006D 00E9 00E8
          ေ + ြ + ပ + ာ + င + ် + း → ပြောင်း
  page 4: 00EE 006A 006D 00E9 00E8
          ြ + ခ + င + ် + း → ခြင်း
  page 12: 00E4 0069 00EA 00DF 00E9
           ေ + က + ျ + ာ + ် → ကျော်

The first 200 pages contain 265 ေ+ြ+base, 1,606 ြ+base, 229
ေ+base+ျ, and 4,133 ေ+base occurrences in this subset. These pattern
counts overlap; they are not independent words. The separate bounded
lookahead for a later ျ was requested earlier but had no matching example in
this 200-page sample. It stops at another base, stack, non-mark or eight-slot
boundary. Only the leading positions are changed; the suffix is preserved.
A compound ZawCode keyboard slot starting with ျ keeps its other marks after
ေ. No general rule for a syllable containing both ြ and ျ has been inferred.

Of 104,626 raw glyph occurrences sampled, 6,961 had no cmap/direct-single
reading and remain unresolved. Other font subsets and pages remain unreviewed.
The helper is partial and is not wired into the production extraction path.
