## 0. Status — read this first

| thing | status |
|---|---|
| **SVG line/frame method for digital pages** | **FINAL DESIGN.** Do not redesign it. |
| **Raster → SVG trace** (`svgout/trace_raster.py`) | **EXPERIMENTAL / SCRATCH**, for the OCR lane only. |

The trace script exists to prove one thing: an image page can be turned into
stroke geometry with round tips instead of staying a bitmap. It is not a
finished component and must not be wired into the parser as-is.

### The final design, in five lines

1. Four rules per line, **equally spaced**, baseline on the third:
   `r1 = b-2E`, `r2 = b-E`, `r3 = b`, `r4 = b+E`.
2. `E = size / 2`. Width comes from **font size alone** — never from a font file.
3. Canvas width is **locked to the page width**, so any two sheets overlay.
   Length is unbounded; it grows as far as the lines go.
4. Coordinates stay in **page space**. No transform is needed to stack a
   single line on the full sheet.
5. `<defs>` is **one per sheet**, shared by every line. Round caps on every
   rule (`stroke-linecap="round"`).

Why `E = size/2`: calibrated once offline from Myanmar3 ink —
`ိ` reaches 0.9389 em above the baseline, `ု` reaches 0.4000 em below.
Binding `E = 0.4694 em`, and both glyphs are 0.4978 em wide, so the round unit
is half an em.

Why not per-font coordinates: this was measured across all 109 faces in the
repo. Whole-font extremes need `E` median 0.495 em but up to **0.861 em**,
because they count glyphs a line never draws. Shaping real text across 104
faces needs only 0.495 median / 0.582 max. So per-font reading is both a
400-file dependency **and** a worse answer. **Do not reintroduce it.**

## 2. Voting and matching rules — keep, update, retire

| rule | today | decision | why |
|---|---|---|---|
| cross-font alias abstention (`shape-alias.json`) | on | **KEEP** | Two faces that draw a pair the same way must not be separated by margin. |
| hand-written orthography rules (`MEDIALS`, `VIRAMA`, `CONSONANT`, `reorderPreBase`) | on | **KEEP** | Not shape problems. Removing them breaks real words. |
| composition entries (`shape-thresholds.json`) | on | **KEEP** | `ည` vs `ညှ` is not confusion; the generator derives these. |
| code-page voting (`scoreCodePage`, `maxDistance .09`) | on | **KEEP — for digital pages only** | Useful when the embedded font is unknown but present. Irrelevant to an image page. |
| `crowdVote` `claimLimit .06` | on | **UPDATE** | Must be calibrated from the same distance metric used by the matcher. Two metrics, two thresholds, one lie. |
| `matchRasterMask` `maxDistance .12` | on | **UPDATE** | Re-derive after the mask/stroke change. |
| page-level raster matching on a text-based PDF | allowed, warned | **RETIRE** | The `console.warn` already says so. Enforce it via §4. |
| fixed 48×48 grid | on | **UPDATE** | See §1 row 2. |

### The known voting failure, and why a threshold cannot fix it

Measured earlier in this workstream with the contour metric:

```
က ~ ယ  0.0177      က ~ လ  0.0264
ယ ~ လ  0.0211      က ~ ဟ  0.0221
threshold                              0.08
```

`က` and `လ` are separated by **0.0264**, well inside every threshold in the
lane. No single distance value will split them without also splitting things
that genuinely are the same. IoU confirms it: `က~လ 0.702`, `ယ~လ 0.788`.

**Consequence for the agent:** the fix is not a tighter number. It is
(a) the alias table carrying the pair, and (b) the verdict in §4 sending the
page to the lane that has real outlines instead of a raster guess.

*(These figures predate the current branch. Re-run them against the shared
metric before they gate anything.)*

## 4. Create a new verdict

Today the parser decides *encoding* (`englishLikeness` → `verdict: "english" |
"not-english"`, consumed by `page-decision.js` and `caller-policy.js`). That is
a text verdict. The vector lane has no verdict at all, which is why the raster
matcher is reachable from a page that never needed it.

**Ask: add a second, orthogonal verdict — a lane verdict — and emit it beside
the existing one, not instead of it.**

Suggested shape:

```js
// B.Parser/main/parser/shape/verdict.js
export const VECTOR_LANES = Object.freeze({
  CONTENT: "content-svg",   // page draws real outlines: use them, never OCR
  TRACED:  "traced-svg",    // image page: trace to stroke geometry, then match
  RASTER:  "raster-match",  // single unresolved crop only
  ABSTAIN: "abstain",
});

export function vectorVerdict(page) {
  // page: { uses, fontItems, textChars, imageCoverage, hasImg, tracedQc }
  const glyphs = page.uses ?? 0;
  const chars  = page.textChars ?? 0;
  const cover  = page.imageCoverage ?? 0;

  if (glyphs > 0 && chars > 0) {
    return { lane: VECTOR_LANES.CONTENT, reason: "outlines-present", exact: true };
  }
  if (cover >= 0.5 && chars < 50) {
    if (page.tracedQc?.ok) {
      return { lane: VECTOR_LANES.TRACED, reason: "image-page", exact: false,
               strokeWidth: page.tracedQc.strokeWidth };
    }
    return { lane: VECTOR_LANES.ABSTAIN, reason: "trace-qc-failed", exact: false };
  }
  return { lane: VECTOR_LANES.ABSTAIN, reason: "no-outlines-no-image", exact: false };
}
```

Rules the verdict must enforce:

1. **`CONTENT` wins whenever outlines exist.** A page with glyph uses is never
   rasterised and never OCR'd, no matter how bad its text is. This is the
   `console.warn` in `match.js` turned into code.
2. **`TRACED` requires QC.** Trace is admitted only when the skeleton is
   continuous (no single-pixel gaps above a set count) and stroke width is
   within the expected band. Otherwise **abstain** — the lane must be able to
   say "I don't know".
3. **`RASTER` is crop-scoped.** One unresolved glyph, not a page.
4. **No lane may silently upgrade itself.** A `TRACED` result is `exact: false`
   and must carry that flag into any text it produces.

Wire it where the existing verdict is consumed (`page-decision.js`,
`caller-policy.js`, `pipeline.js`), and record it in the page report next to
the encoding verdict so a page can read e.g. `content-svg` + `UNICODE`.

## 5. Do not change these

- **Do not compute the frame per font.** Measured worse, and it costs 400 files.
- **Do not rasterise a digital page in order to vectorise it.** The outlines
  are already in the content stream.
- **Do not use nested `<svg x y>`.** MuPDF draws **0 ink** for it. Use
  `<g transform="translate(...)">`.
- **Do not rely on an authored `clip-path` on a group.** MuPDF ignores it.
  Each line carries only its own glyphs, so nothing needs clipping.
- **Do not slice lines out of a flattened SVG** — the baseline is already lost
  by then. Slice from the page export, where `y` is still the baseline.
- **Do not drop the round caps.** They are part of the design, not decoration:
  they are what makes a traced stroke read as ink rather than a cut shape.

as such in their headers. `canvas.py` still carries the old `pitch/3` frame.
