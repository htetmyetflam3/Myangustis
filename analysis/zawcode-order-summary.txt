ZawCode draft: font-scoped extraction and leading-slot order

Source: ယဲ့နင် စာစဉ် a ၁.merged.merged.pdf (4,414 pages).
Reference F1 embedded font SHA-256:
5bc0cd2994aa0178e01efb00f9217e9adb975ba86e77a12e6e8f81268c450de9

The reference uses two-byte Identity-H codes with an Identity CID-to-GID
map; these are glyph IDs, not the ASCII slots in zawcode-layout.js. The
first-200-page order report labels glyphs from cmap and direct GSUB single
substitutions, without /ToUnicode. The draft profile also includes bounded
single-substitution chains and non-joiner ligatures, plus four separately
documented order glyphs inferred from source contexts. All readings remain
provisional; font identity alone does not prove a keyboard layout.

The PDF has 11 separately hashed Myanmar3 subsets that qualified for this
draft. Each has the same derived candidates, identical GSUB table and
context-slot outlines as the reference, and independent leading-order evidence
on at least two sampled pages. Their hashes, page ranges, evidence and raw
examples are in zawcode-font-profiles.json; no subset is selected by name.
The runtime JSON uses one shared template plus a profile for each SHA-256.
A profile can override glyphs, orderGlyphs or alternatives individually;
conflicts and alternatives remain unresolved rather than being guessed.

The 14 investigated glyph IDs, their provisional Unicode readings, example
words, physical PDF pages and exact raw sequences are listed in
zawcode-14-glyph-words.txt. They are separate from the four unresolved IDs.

The original 200-page report has 265 ေ+ြ+base, 1,606 ြ+base,
229 ေ+base+ျ, and 4,133 other ေ+base occurrences. These pattern
counts overlap. The separately confirmed bounded lookahead for a later ျ
had no matching example in this sample; it stops at a base, stack, ြ,
non-mark, or eight-slot boundary. A compound medial stays together; other
suffix slots retain their relative order. A combined ြ+ျ cluster found
within the bounded window is preserved as-is; no combined rule is inferred.

Draft runtime behavior:
  • Auto-select when a profile matches and at least two ေ+ြ+base
    occurrences appear on two of the first 20 pages. Other PDFs use the
    existing path. The heuristic is evidence, not a layout guarantee.
  • PRASER_ZAWCODE_DRAFT=1 explicitly selects a profile when used on the
    probe pages; =0 disables the automatic draft. Library callers can set
    textLayout/text_layout to zawcode, auto, or off.
  • Decode selected resources from their own raw glyph profile, bypassing
    their /ToUnicode; preserve unknown or ambiguous codes as [XXXX]. Reorder
    only adjacent profiled runs, once, during line assembly. Pages without a
    profiled font use the existing extraction path. Generic cleanup/repair
    does not change the profiled draft output.

A full source-stream pass found profiled font runs on 3,580 pages, with
1,907,430 decoded code points. Four unresolved glyph IDs produced 110
visible placeholders: 00FC (69), 00FE (31), 00FD (7), and 00F2 (3). Raw
windows and surrounding provisional text are in zawcode-draft-coverage.json.
The other 834 pages did not use a profiled font; they include different
MyanmarText subsets and remain outside this draft. The existing path can
still produce poor text there. Counts are not an accuracy guarantee, and
Form XObjects are outside the page-stream evidence.
