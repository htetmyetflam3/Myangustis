WHAT WAS TESTED

The current Parser implementation was run through Manager with job extracting,
method default, default cleanup setting, and PDF output. There were 34 jobs and
331 input pages; all jobs completed. They were rerun as Manager TXT jobs and
the returned texts matched the PDF jobs for all 34 cases. The earlier batch
explicitly disabled optional cleanup; all 34 default-setting texts and all
362 rendered output pages matched that batch. Equality is not proof of correct
Burmese, and the generated PDFs still have the defects below.

The batch reads embedded PDF text and graphics; it does not use OCR. Image-only
text and covers are not expected to be transcribed here. The new image/OCR path
was tested separately on one real mixed page and with rotation/offset geometry
tests, not across this 34-file batch.

ISSUES TO INVESTIGATE

* Many result PDFs clip long lines outside the visible page. In 169 of 362
  output pages, more than half the non-space/non-control text characters have
  their centres outside the page, according to PyMuPDF geometry. This is not
  the accepted zero-width-character omission. See output-pages.csv.
* Case 04, source-samples/04.pdf page 3: visible Myanmar vector text gives
  only whitespace/control characters in Parser output, with no warning.
* Case 28, source-samples/28.pdf page 5: a Zawgyi-One header and a WinInnwa
  body share a page. The shared route warns about the legacy font but emits
  Latin/symbol gibberish for the body.
* Case 03, source page 1, and case 24, source page 3, show bracket-hex tokens
  in the Parser text in place of some visible characters. Bracket patterns in
  the aggregate report are not automatically all proven unresolved glyphs.
* The batch logged 23 text-after-checkpoint warnings and 92 encoding/Unicode
  order review warnings. A warning is evidence for inspection, not by itself
  proof of incorrect text.

AUTOMATED TESTS

The focused new-design checks in reports/parser-focused.txt contain 72 tests:
66 passed, none failed, and 6 were skipped.
The complete npm run test:parser log is in reports/parser-test-suite.txt:
115 tests, 101 passed, 6 failed, 8 skipped. The failures are preserved:
- parser-layout.test.js imports a no-longer-exported findModelPath helper;
- scan-placement.test.js expects the old document-wide scan result;
- vector-unknown.test.js S4 and S7, and vector.test.js, expect the old
  vector/legacy route and Myanmar body on an English-prefixed mixed page;
- zawgyi-cmap.test.js expects the old decodeKind value 'cmap' rather than the
  current 'zawgyi-one' path.
These descriptions do not dismiss the missing Myanmar body: it remains a real
limitation under the requested page-prefix routing policy.
